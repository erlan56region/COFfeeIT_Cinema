# SyncWatch — совместный просмотр видео

Веб-сайт для совместного просмотра кино на расстоянии. Создайте комнату, отправьте код друзьям и вставьте ссылку на видео — воспроизведение, пауза и перемотка синхронизируются у всех участников в реальном времени.

![Socket.IO](https://img.shields.io/badge/Socket.IO-4.x-010101?logo=socket.io&logoColor=white)

**Сайт:** <https://erlan56region.github.io/COFfeeIT_Cinema/> — размещён на GitHub Pages и работает без отдельного сервера: участники комнаты соединяются напрямую, браузер с браузером. Как это устроено и какие есть ограничения — в разделе [«GitHub Pages»](#github-pages).

## Возможности

- **Синхронизация просмотра** — play, pause и перемотка применяются у всех участников комнаты
- **Поддержка источников** — YouTube (включая Shorts), Rutube, VK Видео, Vimeo, прямые ссылки на MP4 / WebM и потоки HLS (`.m3u8`)
- **Ссылки на любые сайты** — ссылка появляется у всех участников карточкой с кнопкой «Открыть в браузере»; ссылки в сообщениях чата тоже открываются по нажатию
- **Комнаты по коду** — 6-символьный код, вход по ссылке `?room=XXXXXX`
- **Чат** — с историей сообщений: новый участник видит, о чём говорили до него
- **Реакции** — иконки взлетают поверх видео у всех участников
- **Очередь видео** — несколько ссылок подряд с автопереходом к следующей
- **Список участников** — с метками «Организатор» и «Вы»
- **Адаптивный интерфейс** — телефон, планшет, ноутбук; крупные зоны нажатия
- **Без регистрации** — достаточно ввести имя

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) версии 18 или новее.

```bash
# 1. Установить зависимости
npm install

# 2. Запустить сервер
npm start

# 3. Открыть в браузере
# http://localhost:3000
```

Порт по умолчанию — `3000`. Чтобы изменить:

```bash
PORT=8080 npm start
```

При таком запуске комнаты работают через сам сервер (`server.js`); файл `config.js` на это не влияет.

## Как пользоваться

1. Введите имя и нажмите **«Создать комнату»**.
2. Нажмите на код комнаты в шапке — ссылка-приглашение скопируется. Отправьте её участникам.
3. Вставьте ссылку на видео и нажмите **«Смотреть»**. Видео запустится у всех одновременно.
   - Подходят ссылки на страницу видео YouTube, Rutube, VK Видео (`vk.com`, `vk.ru`, `vkvideo.ru`) и Vimeo, прямые ссылки на видеофайл и на поток HLS (адрес с `.m3u8`). Подробнее — в разделе [«Rutube, VK Видео и потоки HLS»](#rutube-vk-видео-и-потоки-hls).
   - В то же поле можно вставить ссылку на любой другой сайт (подойдёт и адрес без `https://`, например `kinopoisk.ru/film/326`). Вместо плеера у всех появится карточка с адресом и кнопками **«Открыть в браузере»** и **«Скопировать ссылку»** — каждый открывает сайт у себя в новой вкладке.
4. Обсуждайте в чате, ставьте реакции, добавляйте следующие видео в очередь кнопкой **«В очередь»**.

## Как работает синхронизация

Сайт работает в одном из двух режимов. Какой из них включён, определяет файл `config.js`:

- **без сервера** — в `config.js` пусто. Так сайт работает на GitHub Pages;
- **со своим сервером** — в `config.js` указан адрес сервера, либо сайт открыт через `npm start`.

Логика в обоих режимах одна. Для каждой комнаты хранится текущее видео, статус (`playing`), позиция и метка времени старта. При запросе состояния позиция вычисляется как `position + (сейчас − startedAt)` для играющей комнаты.

Клиент отправляет события `play` / `pause` / `seek`, они рассылаются остальным участникам, и те выравнивают своё время. Раз в 15 секунд клиент запрашивает `sync_request`, и при расхождении больше 2,5 секунд плеер подтягивается к общему времени.

### Режим без сервера

Участники соединяются напрямую, браузер с браузером (технология WebRTC). Найти друг друга им помогает бесплатный общедоступный сервис [PeerJS](https://peerjs.com): он только «знакомит» браузеры между собой, а события просмотра и сообщения чата идут от участника к участнику.

- Браузер организатора (того, кто создал комнату) выполняет роль сервера: хранит состояние комнаты и рассылает события остальным.
- У каждого участника есть копия состояния. Если организатор вышел, комнату подхватывает следующий по порядку входа участник, а остальные переподключаются к нему.
- Комната существует, пока в ней есть хотя бы один участник.

Код этого режима — в файле `p2p.js`. Для остального кода сайта он выглядит как сокет Socket.IO с теми же событиями, поэтому интерфейс в обоих режимах один и тот же.

## Rutube, VK Видео и потоки HLS

**Rutube и VK Видео** показываются в комнате собственными плеерами этих сервисов — так же, как YouTube и Vimeo. Сайт управляет плеером способом, который описали сами сервисы: [Rutube](https://rutube.ru/info/embed/), [VK Видео](https://dev.vk.com/ru/widgets/video).

- Распознаются ссылки `rutube.ru/video/…`, `rutube.ru/shorts/…`, `rutube.ru/video/private/…?p=…` (видео «по ссылке»), `vk.com/video-1_2`, `vkvideo.ru/video-1_2`, `vk.com/clip-1_2`, ссылки с `?z=video-1_2` и адрес из кода для вставки (`video_ext.php?oid=…&id=…&hash=…`).
- Запуск, пауза и перемотка общие — и кнопками сайта, и кнопками внутри самого плеера.
- Рекламу плеер показывает каждому зрителю свою. На это время его видео живёт отдельно от комнаты, а после рекламы возвращается на общее место. Если реклама началась у того, кто запустил видео, комната продолжит с места, где видео остановилось, — начало никто не пропустит.
- Если браузер не дал плееру начать воспроизведение без нажатия (так бывает на телефонах и в Safari), сайт подскажет нажать на кнопку воспроизведения в самом плеере.
- Плеер VK Видео и библиотека для управления им загружаются с сайта `vk.com`; если он не ответил, сайт пробует `vk.ru`. Плеер Rutube загружается с `rutube.ru`.
- Если плеер не отвечает 20 секунд, под кнопками управления появляется пояснение. Чтобы увидеть сообщения плеера в консоли браузера, добавьте к адресу сайта `?debug`.

**Потоки HLS** — это адреса, в которых есть `.m3u8`. Safari и часть других браузеров воспроизводят их сами; в остальных поток воспроизводит библиотека [hls.js](https://github.com/video-dev/hls.js) из папки `vendor/`. Она загружается только тогда, когда понадобилась.

- У записи (потока с известной длительностью) запуск, пауза и перемотка общие, как у видеофайла.
- У прямого эфира общие только запуск и пауза: шкала времени у каждого зрителя своя, поэтому перемотка отключена, а запуск возвращает зрителя к тому, что идёт сейчас.

Страницы других сайтов (онлайн-кинотеатры, сайты с собственным плеером) в комнате не воспроизводятся: браузер не даёт одному сайту ни читать содержимое другого, ни управлять его плеером. Такая ссылка остаётся карточкой «Открыть в браузере». Если у видео есть прямой адрес файла или потока `.m3u8` и его владелец разрешает воспроизведение на других сайтах, в комнату можно вставить этот адрес.

## API и события Socket.IO

| Событие (клиент → сервер) | Назначение |
|---|---|
| `create_room` | создать комнату (`name`, `color`) |
| `join_room` | войти в комнату (`roomId`, `name`, `color`) |
| `set_video` | установить текущее видео или ссылку (`url`, `type`: `youtube`, `vimeo`, `rutube`, `vk`, `direct` — видеофайл или поток HLS, либо `link` — ссылка на сайт; `title`) |
| `play` / `pause` / `seek` | управление воспроизведением (`time`) |
| `sync_request` | запросить актуальное состояние |
| `chat_message` | отправить сообщение (`text`, до 500 символов) |
| `reaction` | реакция (`heart`, `fire`, `laugh`, `wow`, `clap`, `sad`, `party`) |
| `queue_add` / `queue_remove` / `queue_next` | работа с очередью |

| Событие (сервер → клиент) | Назначение |
|---|---|
| `room_created` / `room_joined` | состояние комнаты после входа |
| `video_changed` | сменилось видео |
| `remote_play` / `remote_pause` / `remote_seek` | команды других участников |
| `sync_state` | актуальное состояние для выравнивания |
| `users_update` | обновился список участников |
| `chat_message` / `system_message` | сообщения чата и системные заметки |
| `queue_update` | обновилась очередь |
| `app_error` | сообщение об ошибке для пользователя |

В режиме без сервера события те же, только передаются между браузерами участников.

HTTP-эндпоинт `GET /api/health` есть только у сервера, он возвращает `{ "ok": true, "rooms": N }`.

## Развёртывание

Сайт — это статические файлы: `index.html`, `style.css`, `app.js`, `p2p.js`, `config.js`, `images/`, `vendor/`. Разместить его можно двумя способами:

1. **Только сайт, без сервера** — GitHub Pages или любой хостинг файлов. Настраивать ничего не нужно: комнаты работают напрямую между браузерами участников.
2. **Со своим сервером** (`server.js`, Node.js) — Render, Railway, свой VPS. Комнаты хранит и рассылает события сервер. Этот способ надёжнее: он не зависит от стороннего сервиса и работает в сетях, где прямые соединения между браузерами заблокированы.

### GitHub Pages

Сайт открывается по адресу <https://erlan56region.github.io/COFfeeIT_Cinema/>. В настройках репозитория (**Settings → Pages**) должно быть выбрано **Deploy from a branch**, ветка `main`, папка `/ (root)`.

Комнаты на нём работают без сервера — см. [«Режим без сервера»](#режим-без-сервера). У этого режима есть ограничения:

- Сайт зависит от бесплатного общедоступного сервиса PeerJS, который работает без гарантий. Если сервис недоступен, создать комнату или войти в неё не получится — сайт покажет сообщение «Не удаётся установить связь».
- В некоторых сетях (корпоративные, часть мобильных, VPN) прямое соединение между браузерами не устанавливается. Тогда участник видит сообщение «Комната найдена, но соединиться с её организатором не удалось». Обычно помогает другая сеть или отключение VPN.
- Если организатор вышел из комнаты, её сразу подхватывает другой участник. Если у организатора внезапно закрылся браузер, пропал интернет или «уснул» телефон, остальные замечают это примерно через 15 секунд и ждут: либо организатор вернётся, либо его место займёт другой участник. Ожидание может длиться больше минуты — пока сервис PeerJS не освободит адрес комнаты. В это время видео у остальных продолжает идти, но команды и сообщения чата не передаются.
- В комнате может быть до 30 участников.
- Участники соединены с организатором напрямую, поэтому их IP-адреса технически видны друг другу.

Если эти ограничения мешают, подключите свой сервер:

1. Разверните сервер — например, на Render (инструкция ниже). Вы получите адрес вида `https://syncwatch-xxxx.onrender.com`.
2. Откройте в репозитории файл [`config.js`](config.js), нажмите на карандаш (**Edit this file**) и впишите этот адрес в последнюю строку:

   ```js
   window.SYNCWATCH_SERVER = 'https://syncwatch-xxxx.onrender.com';
   ```

   Адрес должен начинаться с `https://`.
3. Сохраните изменение в ветку `main` (**Commit changes**). Через одну-две минуты GitHub Pages опубликует его — обновите страницу сайта.

Проверить, что сервер запущен, можно, открыв в браузере `https://ВАШ-АДРЕС/api/health` — придёт ответ вида `{"ok":true,"rooms":0}`. Чтобы вернуться к режиму без сервера, снова оставьте в `config.js` пустую строку.

> На бесплатном тарифе Render сервер «засыпает» после 15 минут без посетителей и просыпается примерно за минуту. В это время сайт показывает «Подключаемся…» и подключается сам, как только сервер ответит.

### Render

1. Загрузите репозиторий на GitHub.
2. На [render.com](https://render.com) → **New → Web Service** → выберите репозиторий.
3. Build Command: `npm install`, Start Command: `npm start`.
4. Готово — Render выдаст публичный адрес.

### Railway

1. [railway.app](https://railway.app) → **New Project → Deploy from GitHub repo**.
2. Railway сам определит Node.js и запустит `npm start`.

### Свой VPS

```bash
git clone https://github.com/erlan56region/COFfeeIT_Cinema.git
cd COFfeeIT_Cinema
npm install --omit=dev
PORT=3000 node server.js
```

Для постоянной работы используйте `pm2` или `systemd`, а для HTTPS — обратный прокси (Nginx + Certbot).

> **Важно:** комнаты хранятся в памяти процесса. При перезапуске сервера они пропадают — для сохранности подключите базу данных (Redis, MongoDB).

## Известные ограничения

- Комнаты нигде не сохраняются: комната исчезает, когда из неё вышел последний участник, а в режиме со своим сервером — ещё и при перезапуске сервера.
- Режим без сервера зависит от стороннего сервиса PeerJS и от сети участников — подробнее в разделе [«GitHub Pages»](#github-pages).
- Встроенное воспроизведение зависит от правообладателя: некоторые видео YouTube и Vimeo запрещают показ на сторонних сайтах. В этом случае сайт покажет пояснение и ссылку «Открыть в новой вкладке».
- Ссылки на видеохостинги с защитой (например, страницы с DRM) не поддерживаются — нужна прямая ссылка на файл.
- Rutube и VK Видео: автор видео может запретить показ на других сайтах — тогда плеер сам напишет об этом в своём окне. Реклама у каждого зрителя своя, и пропустить её сайт не может. VK Видео сообщает время целыми секундами, поэтому зрители могут расходиться в пределах секунды. В Firefox и Safari с включённой защитой от отслеживания плеер VK Видео может не работать — об этом предупреждает сам VK.
- Потоки HLS: сервер потока должен разрешать воспроизведение на других сайтах (заголовки CORS), иначе в браузерах, где поток воспроизводит hls.js, он не загрузится. Потоки с защитой DRM не поддерживаются. У прямых эфиров нет общей перемотки, и зрители могут отставать друг от друга на несколько секунд.
- Ссылка на сайт только показывается участникам: сам сайт внутри комнаты не открывается (большинство сайтов запрещают встраивать себя в другие страницы), и то, что каждый делает на нём у себя, не синхронизируется. Общими остаются ссылка, чат и реакции.
- Чтобы отличить страницу сайта от видеофайла без расширения в адресе, браузер каждого участника один раз запрашивает присланный адрес — так же, как раньше запрашивал любую ссылку на видео. Если по адресу оказалось видео, вместо карточки появляется обычный плеер с синхронизацией. Сайт, на который ведёт ссылка, при этом видит обращение от каждого участника, даже если тот не нажимал «Открыть в браузере».
- Синхронизация рассчитана на небольшие компании (до нескольких десятков человек в комнате).
